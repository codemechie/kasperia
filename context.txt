GOAL:
Build AI Agent (RAG-based, no LLM training) that searches 10-50 e-commerce sites for products.
Uses MCP server for data-fetching tools + local Mistral/Qwen (Ollama) for orchestration.

CURRENT STATE:
- Direct Site Scraping architecture is implemented.
- DuckDuckGo, Google CSE, and SearXNG approaches abandoned (rate limits / paywalls / instability).
- Nike scraper is working. Adidas scraper has anti-bot issues (returns error page on direct requests).

FILE STRUCTURE:
├── server.py              # FastMCP server with search_products tool
├── agent.py               # Client: Ollama Qwen → tool call → search_products → print JSON

ARCHITECTURE:
User Prompt → Ollama (qwen2.5:7b) → tool_choice="auto"
  → Qwen calls search_products(prompt, brands, min_price, max_price)
    → server.py dispatches to scrapers/{brand}.py
      → scraper.search(prompt) → list[product dicts]
    → Filters by price range (INR, with USD→INR conversion at 83)
    → Calculates VFM = price_factor * 5 (rating unavailable on listing pages)
  → Returns JSON array of {vendor, make, price, vfm, rating, reviews_count, url}

SCRAPER INTERFACE:
All scrapers implement .search(query: str) → list[dict]
Each dict has keys: vendor, make, price, currency, rating, reviews_count, url
New scrapers should follow this interface and be registered in scrapers/__init__.py

NIKE SCRAPER (scrapers/nike.py):
- URL: https://www.nike.com/w?q={query}
- Nike uses Next.js. Product data is in the __NEXT_DATA__ script tag as JSON.
- Data path: props → pageProps → initialState → Wall → productGroupings → [{products: [...]}]
- Each product has: copy.title, copy.subTitle, prices.currentPrice, pdpUrl
- pdpUrl can be string or dict (with 'url' and 'path' keys) — _resolve_url() handles both
- Deduplication by groupKey (same shoe model, different colors/sizes)
- Picks lowest price when multiple variants exist for same groupKey
- 22 unique products per query (down from 264 variants)
- Fallback: parse HTML product-card elements (if __NEXT_DATA__ fails)

ADIDAS SCRAPER (scrapers/adidas.py):
- URL: https://www.adidas.com/us/search?q={query}
- Adidas returns a bot-blocking/error page to automated requests
- _find_embedded_json() scans all script tags for valid JSON with product-like keys
- _is_product_data() heuristically checks if JSON contains itemListElement, items, or products
- Currently returns empty results. Requires anti-bot solution (Playwright, TLS fingerprinting, etc.)

SERVER.PY (server.py):
- search_products() tool:
  1. Determines target scrapers from brands param (or uses all scrapers)
  2. Each scraper.search(prompt) returns raw product list
  3. USD prices converted to INR at USD_TO_INR = 83
  4. Products outside [min_price, max_price] are dropped
  5. VFM = max(0.1, (6000 - price_inr) / 3000) * 5  (rating unavailable, so pure price score)
  6. Returns JSON array sorted by scraper order
- extract_product_data() utility function preserved (generic page parser via JSON-LD + OG tags)
- No API keys required. No external dependencies besides requests + bs4 + lxml.

AGENT.PY (agent.py):
- Uses OpenAI-compatible client to talk to Ollama at 127.0.0.1:11435
- Tool definition: search_products with optional brands, min_price, max_price
- Only 'prompt' is required — Qwen decides which brands/price range based on user input
- Fallback parser (_parse_tool_call) handles models that return JSON in content string
