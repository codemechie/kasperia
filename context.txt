GOAL:
AI Agent that searches 10-50 e-commerce sites for best deals. No LLM training — pure RAG + tool calling.
Ollama (Qwen/Mistral) orchestrates via MCP tool server.

ARCHITECTURAL OVERVIEW (Multi-Agent System)

Phase 1 — Abstract interface over direct scrapers with 3-layer server-side lookup.
Phase 2 — Self-healing multi-agent loop: missing scrapers are generated on the fly
by an LLM code-gen agent, validated in an isolated evaluator, and live-deployed.

TWO LLM ROLES:
  • agent.py —  Orchestrator: user-facing Qwen that decides which store to query
                via search_products tool call.
  • worker.py — Code-Gen Agent: background Qwen that reverse-engineers a store's
                DOM structure into a runnable Python scraper class.

LAYERED DATA FLOW:
  User Prompt → Ollama (tool_choice="auto") → search_products(query, domain)
    → Layer 1: state.cache (instant return)
    → Layer 2: state.scraper_registry (async BaseScraper.scrape_products)
    → Layer 3: Queue agent build + fallback parser (JSON-LD / OG meta)
               ↓
          worker.py picks up the queue job:
               ├── fetch_target_dom_sample() → structural HTML snippet
               ├── run_llm_codegen_agent() → Ollama generates Scraper class
               └── load_agent_scraper() → compiles, validates, live-deploys
                    into state.scraper_registry for future Layer 2 hits
